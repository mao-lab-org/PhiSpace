## Inputs and scope

The preparation script downloads `allTissues1.rda`, `allTissues2.rda`,
`allTissues3.rda` and `multiClustRes.rda` directly from the pinned commit.
The four source-file SHA-256 values are in `cosmx-multisample-inputs.tsv`.
Their combined download size is 235,125,772 bytes. The public download route
was tested independently of the local workshop checkout; all four hashes
matched. The restored qs2 objects were identical to the loaded RDA objects.

The three tissue lists contain eight sections, 350,228 uniquely named cells
and the same 81 score columns from five references. The cells per section are
46,526; 48,726; 45,772; 41,858; 38,522; 57,442; 33,202; and 38,180, in the
article's declared order. These are the workshop's supplied 50% subsample,
not the full four-reference data used in `CosMx.Rmd`.
The objects have a one-row placeholder assay, so reference fitting cannot be
reproduced from these inputs. “Fresh” here refers to downstream calculations
and the clustering comparison, not a fresh annotation.

The embedded `multiSampClust` metadata have ten labels. The archived chapter
explicitly overwrites them with the separate nine-cluster `multiClustRes`
object; this article follows that operation using cell IDs, not positions.

## Historical clustering comparison

All comparisons used smoothing within each section (`kernel = "gaussian"`,
`k = 15`, `include_self = TRUE`) and the same concatenation order. K-means
used 30 PCs, nine clusters, Lloyd's algorithm, 20 starts, 1,000 iterations,
centred/unscaled scores, and seed 83904.

| Computation | Adjusted Rand index against saved labels |
| --- | ---: |
| Current `clusterPhiSpace()` | 0.757357144607862 |
| Historical PCA and k-means calculations | 1 |
| Current SVD scores, restoring the historical post-PCA RNG state before k-means | 1 |

The first 30 old and new PCs agree after sign alignment: maximum score
difference 1.482703e-12; maximum component-standard-deviation difference
1.526557e-15. The discrepancy comes from random-number consumption before
k-means, rather than a different leading PCA subspace. The historical PCA
asked irlba for 80 of 81 components; it draws a random start, while the
current full SVD does not. Matching cluster numbers by maximum overlap gives
89.200749% agreement for the current wrapper, but does not alter memberships.

The article therefore retains the saved nine-cluster partition for its maps
and scientific examples. A fresh publishing build independently recomputes
the current clustering and reports the comparison; it does not claim that
the saved labels were regenerated by the current wrapper.

The optional `validate-cosmx-multisample.R` script repeats the historical and
controlled-RNG comparisons without installing an old PhiSpace package. Its
near-full irlba call deliberately retains the historical calculation and
warning for this diagnostic only. It is not the published clustering method.

## Compatibility and interpretation corrections

- `VizSpatial(groupBy = ...)` became `VizSpatial(colBy = ...)`.
- Workshop package `data()` calls and private Dropbox paths were replaced by
  verified, pinned inputs and checksum-validated qs2 reads.
- Clustering settings previously supplied by defaults are explicit.
- The article separates the current clustering comparison from the preserved
  workshop partition. It never transfers a biological interpretation based
  only on a matched numeric label.
- The archived DWD contrast calls niches 1, 3 and 6 cancer niches. In the
  supplied nine-cluster partition their pathology-labelled tumour fractions
  are 0.9261, 0.1276 and 0.4384. The new example defines its contrast explicitly:
  niches with more than half of their pathology-labelled cells labelled
  `Tumour`, giving **1, 2, 4 and 5**. This is a documented change to the
  illustrative target, so DWD values are a new baseline, not claimed to
  reproduce the archived DWD target. The threshold is exploratory.
- Score correlation is described as co-presence, not evidence of contact,
  communication or causation. Shared references do not guarantee removal of
  batch effects. Repeated sections are not treated as independent patients.
- Niche boxplots select the top five states by median unsmoothed score, as
  in the workshop, but calculate quantiles and whiskers before plotting.
  This avoids reshaping 28 million entries solely for a figure. Outliers
  are omitted from the display. The underlying scores and cells are retained.

## Build checks

The 45 expected result metrics in `cosmx-multisample-results.tsv` cover input
dimensions and names, seven tumour-signature rankings, historical clustering
agreement, the current k-means objective, all nine preserved niche sizes and
their tumour fractions, the 64 correlation matrices of 3,240 pairs each,
PCA score sums of squares and the seeded DWD fit. Frozen counts, labels and
rankings must match exactly. Continuous summaries use absolute tolerances
around 1e-5 relative to their scale; small means use the matching SD's scale.
Current-clustering agreement diagnostics allow 0.02 across numerical systems;
these do not affect the frozen memberships used downstream.

The first complete analysis/render took 159.40 seconds and peaked at
5,006,245,888 bytes resident memory (about 4.66 GiB), before the expected-value
file was created. Its 45 metrics then passed against the reviewed values.
The final builds both passed all 45 checks:

| Mode | Elapsed time | Maximum resident memory |
| --- | ---: | ---: |
| Fresh downstream analysis and current-clustering comparison | 159.06 s | 5,164,548,096 bytes |
| Cached current clustering, fresh downstream analysis | 22.40 s | 3,017,572,352 bytes |

All 45 observed metrics were identical between the final builds, and all
nine figures were byte-identical. Cached clustering was not rewritten.
The staged articles index links to `CosMxMultiSample.html`. Figures and
tables were inspected in the rendered article; the wide tumour-signature
table scrolls within its container. The package source archive also built
successfully; the new article and scripts remain excluded from that archive.

The preparation script rejected a deliberately corrupted source input before
conversion, and cached mode rejected a deliberately corrupted result/hash.
Cached mode checks the saved result's SHA-256 before staging, and checks it
again after rendering to reject any rewrite.

Local environment: R 4.6.0, macOS arm64, PhiSpace 0.99.0, SpatialExperiment
1.22.0, qs2 0.2.2, pkgdown 2.2.1, irlba 2.3.7, kerndwd 2.0.3, vizOmics 0.1.0.
The existing workflow remains pinned to R 4.5.0, Ubuntu 24.04 and pkgdown 2.2.0;
runner validation will occur after the user pushes.

The full package test suite gave 471 passing expectations and two numerical
failures, both also reproduced in an untouched checkout of the implementation
base: `test-getPC.R:93` (partial irlba scores versus prcomp) and
`test-mvr.R:68` (PCA regression coefficients versus prcomp). No package code
or test tolerance was changed to address those pre-existing failures.

## Reproduce locally

From the active package repository, choose absolute paths outside the clone:

```sh
export PHISPACE_COSMX_MULTISAMPLE_INPUTS=/path/to/cosmx-workshop-inputs
export PHISPACE_COSMX_MULTISAMPLE_RUN_DIR=/path/to/new-fresh-analysis
export PHISPACE_SITE_DIR=/path/to/new-staged-site
Rscript --vanilla scripts/build-cosmx-multisample.R

export PHISPACE_COSMX_MULTISAMPLE_MODE=cached
export PHISPACE_COSMX_MULTISAMPLE_RESULTS=/path/to/new-fresh-analysis/output
export PHISPACE_COSMX_MULTISAMPLE_RUN_DIR=/path/to/new-cached-analysis
export PHISPACE_SITE_DIR=/path/to/new-cached-site
Rscript --vanilla scripts/build-cosmx-multisample.R

# Optional diagnostic of the historical random-state difference:
Rscript --vanilla scripts/validate-cosmx-multisample.R
```

Each analysis-directory path must not already exist. Input caches can be
reused. CI runs the fresh mode; no new data upload or cached analysis result
is required for publication.
